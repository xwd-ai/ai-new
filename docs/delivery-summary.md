# 阶段性交付说明（模块 1/2/3）

本文汇总认证（模块 1）、订单（模块 2）、工单（模块 3）三个模块的交付范围、能力清单、接口约定、错误口径、验证方式与已知限制，作为阶段性交付的说明材料。

对话编排、知识库检索与前端页面属于另一侧的交付范围，本文只在必要处说明交界约定，不展开实现细节。

## 交付范围

| 模块 | 职责 | 主要文件 |
|---|---|---|
| 模块 1 认证 | 密码哈希与策略、JWT 签发与校验、续期、登出与失效、会话清理、角色权限依赖 | `models/user.py`、`schemas/auth.py`、`services/auth.py`、`services/password.py`、`api/auth.py` |
| 模块 2 订单 | 版本能力矩阵、服务期判定、服务范围综合判定、多订单、状态机、续费提示、归档、管理员视图、只读查询工具 | `models/order.py`、`schemas/order.py`、`services/orders.py` |
| 模块 3 工单 | 幂等建单、状态机与时间线、两阶段确认、列表与详情、转人工判定、批量操作、统计、权限 | `models/ticket.py`、`schemas/ticket.py`、`services/tickets.py`、`api/tickets.py` |

三个模块共用同一套 SQLite 数据库与 SQLAlchemy 会话，接口统一挂载在 `/api` 前缀下；订单接口与工单接口由同一个路由实例提供（`api/tickets.py`），因此订单接口的错误码族沿用 `TICKET_`，订单业务错误另用 `ORDER_` 区分（见[错误码分族](#错误码分族)）。

## 模块 1 · 认证

### 密码存储

- 密码以 bcrypt 哈希落库，字符串自描述算法与成本，固定 60 字符（`$2b$` + 两位成本 + 盐与摘要）。
- 成本因子默认 12，可用环境变量 `BCRYPT_COST` 调整，超出 4–16 的取值收敛到区间边界。
- bcrypt 只处理前 72 字节，超长密码直接拒绝而不是静默截断；入参非字符串、空串一律判为校验失败，不抛异常向上冒泡。
- 账号不存在时用占位哈希消耗一次校验，使「账号不存在」与「密码错误」两条失败分支耗时接近，避免通过响应时间枚举账号。
- 旧版摘要账号在登录校验通过后原地升级为 bcrypt，升级只发生一次；已是同等强度哈希时不再改写。

### 令牌

| 令牌 | 类型声明 | 默认有效期 | 可配置区间 |
|---|---|---|---|
| 访问令牌 | `typ=access` | 30 分钟 | 60 秒 – 7 天（`AI_NEW_JWT_TTL`） |
| 续期令牌 | `typ=refresh` | 30 天 | 1 小时 – 180 天（`AI_NEW_JWT_REFRESH_TTL`） |

- 签名算法 HS256，签发方 `ai-new`，受众 `ai-new-web`；声明包含 `iss`/`aud`/`sub`/`username`/`role`/`typ`/`iat`/`nbf`/`exp`/`jti`。
- 时钟偏差余量默认 30 秒，可用 `AI_NEW_JWT_LEEWAY` 调整，上限 300 秒。
- 令牌长度上限 4096 字符，超长直接拒绝，不做无谓解码。
- 密钥取自环境变量 `AI_NEW_JWT_SECRET`，要求不少于 32 字节；未配置时回退固定开发密钥并输出告警，**生产部署必须显式配置**。

### 续期与登出

- 续期令牌登记在 `refresh_tokens` 表，换发访问令牌时校验：是否登记、主体是否一致、是否已吊销、是否已过期。
- 换发不轮换续期令牌，原令牌可用至自身过期；新签发的访问令牌同时登记 `sessions` 表，保证对话链路同步获得登录态。
- 登出把令牌 `jti` 写入 `revoked_tokens` 黑名单，并删除对应 `sessions` 行；已过期的访问令牌仍允许登出（签名与声明照常校验），避免用户卡在「令牌过期但会话残留」的状态。
- 黑名单与吊销记录只在令牌到期前有意义，`POST /api/sessions/cleanup` 按 `sessions`/`refresh_tokens`/`revoked_tokens` 三表清理过期行，保留窗口 0–30 天、单表单批上限 10000 条。

### 角色与权限

- 角色只有 `admin` 与 `customer` 两种，取值经统一归一化（大小写、空白），白名单外落为 `customer`。
- **令牌里的 `role` 声明不作为授权依据**：每次请求按 `sub` 回库确认当前角色，改库即生效，提权伪造声明无效。
- 权限判定收敛到单一出口：`require_login`（401）、`require_role` / `require_admin`（403，附 `required_roles` 与 `role`），并在 FastAPI 侧暴露为 `Depends` 依赖。
- 管理路由的权限依赖先于字段校验执行：未登录或普通用户携带非法入参时仍先收到 401/403，不会被 422 抢先。

### 接口

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /api/login` | 无需登录 | 登录，签发访问令牌与续期令牌 |
| `POST /api/register` | 无需登录 | 注册客户账号，含用户名与密码强度校验 |
| `POST /api/refresh` | 凭续期令牌 | 换发访问令牌（体或请求头二选一） |
| `POST /api/logout` | 凭访问令牌 | 登出，作废访问令牌与会话，可选作废续期令牌 |
| `POST /api/sessions/cleanup` | 管理员 | 清理三张令牌表的过期记录 |
| `GET /api/me` | 可匿名 | 当前登录身份；**未登录恒返回 200 且 `user=null`**，是本模块唯一不使用 401 表示未登录的接口 |

字段与错误示例见 [认证 API](auth-api.md)。

## 模块 2 · 订单

### 版本能力矩阵

| 版本 | 包含能力 |
|---|---|
| 基础版 | 基础导出、单文件上传、社区支持 |
| 专业版 | 基础版全部能力 + 批量导出、高级报表、优先客服支持、API 接口 |

版本取值支持中英文别名（专业版 / 专业 / professional → `pro`），无法识别时返回 `tier_unknown`，不猜测默认版本。功能解析先精确匹配功能码与全名，再按单向最长包含匹配别名——「导出」不会被「批量导出」抢走。

### 服务期判定

服务期按起止时间推导，左闭右开，结果为四态之一：`active`（服务中）、`not_started`（未开始）、`expired`（已到期）、`unknown`（起止缺失或颠倒）。同时给出已用天数（向下取整）、剩余天数（向上取整）、使用百分比与展示文案。

订单状态（`active`/`expired`/`cancelled`）与服务期状态**各自独立**：状态有效的订单也可能处于未开始或已到期，两者不能互相推导。

### 服务范围判定

`evaluate_service_scope` 是纯函数，按固定顺序逐层收紧，命中即返回：

| 顺序 | 原因码 | 含义 |
|---:|---|---|
| 1 | `no_order` | 未查询到订单记录 |
| 2 | `tier_unknown` | 无法识别所购版本 |
| 3 | `order_inactive` | 订单状态非有效（过期、退订或不可识别） |
| 4 | `not_started` | 服务期尚未开始 |
| 5 | `expired` | 服务期已结束 |
| 6 | `period_unknown` | 起止时间不完整 |
| 7 | `feature_unknown` | 无法识别要确认的功能 |
| 8 | `feature_not_included` | 当前版本不包含该功能 |
| 9 | `in_service` | 在服务范围内 |

放行条件为「版本可识别 且 服务期在期内 且 状态有效 且 功能包含」，任一不满足即拒绝，且拒绝原因可回查。

### 多订单与续费

- 一个用户可持有多条订单，主订单按到期时间最晚选取；跨订单判定某功能时取能力并集，并以 `covered_by` 指明覆盖该功能的订单。
- 续费提示按剩余天数分级：30 天窗口进入「即将到期」，7 天内进入「紧急」，已到期进入「待续费」。状态不可识别时给 `unknown` 并建议人工核实，不给出误导性的续费建议。
- 归档接口 `POST /api/order/expire` 只把「状态有效且服务期已到期」的订单置为 `expired`，退订与未开始订单不动；重复调用幂等，单批上限 500 条。

### 接口

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/order` | 可匿名 | 主订单与服务范围摘要，固定 7 键 |
| `GET /api/order/list` | 需登录 | 全部订单、主订单与在期能力并集 |
| `GET /api/order/scope` | 需登录 | 单条订单的完整判定过程 |
| `GET /api/order/feature-scope` | 需登录 | 跨全部订单判定某功能是否在范围内 |
| `GET /api/order/renewal` | 需登录 | 续费提示汇总 |
| `GET /api/order/admin` | 管理员 | 订单列表，支持筛选、分页、排序 |
| `GET /api/order/admin/{order_id}` | 管理员 | 订单详情，含状态流转可选目标 |
| `POST /api/order/expire` | 管理员 | 批量归档已到期的有效订单 |

同一套判定逻辑另以只读工具 `query_order` 的形式供对话链路调用，见[订单工具化说明](order-tool.md)；字段与示例见[订单 API](orders-api.md)。

## 模块 3 · 工单

### 幂等建单

建单以「用户 + 规范化后的问题描述」生成去重键，落库时受唯一约束保护，临界区用数据库 advisory lock 串行化。同一用户对同一问题仍有未解决工单时返回原工单并标明本次未新建，不会产生重复工单；原工单已解决后可再次建单。

### 状态机

| 当前状态 | 允许流转到 |
|---|---|
| `pending_confirm` 待确认 | `open`、`closed` |
| `open` 待处理 | `in_progress`、`resolved`、`transferred_human`、`closed` |
| `in_progress` 处理中 | `resolved`、`transferred_human`、`closed` |
| `resolved` 已解决 | `closed` |
| `transferred_human` 已转人工 | `in_progress`、`resolved`、`closed` |
| `closed` 已关闭 | 终态，不可再流转 |

未列出的流转一律拒绝，错误体同时给出前后状态；状态值不可识别与流转非法分开给码，前者是入参问题（422），后者是业务规则拒绝（409）。

每次状态变化在 `ticket_status_logs` 落一条记录（原状态、新状态、操作人、时间），建单首条的「原状态」记为空串。工单详情返回完整时间线，人工回复与系统消息分区呈现。

### 两阶段建单

建单先创建 `pending_confirm` 草稿，向用户确认后才流转为 `open`：

- 确认接口幂等，已非待确认状态时原样返回；
- 取消接口把草稿置为 `closed` 并记录原因；
- 待确认默认 30 分钟超时，超时收敛为 `closed`，批量上限 500 条，阈值与批量参数越界直接拒绝而不是静默拉回。

### 列表与详情

- 列表支持多状态筛选、关键词搜索（描述、工单号、客户名，字面量匹配，`%`/`_` 不作通配符）、分页（默认 20，上限 100）与时间正逆序；排序以创建时间为主、工单号升序兜底，保证翻页不重不漏。
- 详情包含问题描述、已尝试步骤、排查依据、回复时间线与状态时间线；回复超过 100 条时只保留最近 100 条并标记截断。

### 转人工

判定规则三条，命中即给出原因码，可按规则自动转人工或由客服手动转人工：

| 原因码 | 触发条件 |
|---|---|
| `user_requested` | 用户文本中出现「转人工 / 人工客服 / 联系客服」等诉求 |
| `out_of_scope` | 订单判定为超出服务范围（细分未查询到订单、服务已到期、不包含该功能） |
| `scope_unverified` | 服务范围无法自动核实（版本、服务期或功能名不可识别），不计入超范围 |
| `ineffective_retries` | 已尝试步骤达 3 步，或人工回复达 2 次仍无进展 |

转人工说明以 `kind=transfer` 写入回复时间线，附带原因码与操作人；未给出原因时回填判定原因，仍为空则使用默认说明，保证每次转人工都可追溯。

### 接口

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /api/tickets` | 需登录 | 建单（幂等），返回是否新建 |
| `GET /api/tickets` | 需登录 | 列表，支持筛选、搜索、分页、排序 |
| `GET /api/tickets/{ticket_id}` | 需登录 | 详情，含回复与状态时间线 |
| `POST /api/tickets/confirm` | 需登录 | 确认草稿，`pending_confirm` → `open` |
| `POST /api/tickets/cancel` | 需登录 | 取消草稿，`pending_confirm` → `closed` |
| `GET /api/tickets/pending` | 需登录 | 待确认工单列表，含剩余时间与是否超时 |
| `POST /api/tickets/expire` | 管理员 | 批量关闭超时草稿 |
| `POST /api/tickets/reply` | 管理员 | 追加人工回复，待处理工单随回复推进到处理中 |
| `POST /api/tickets/status` | 管理员 | 状态流转 |
| `GET /api/tickets/{ticket_id}/transfer-decision` | 需登录 | 只读查看转人工判定结果，不改状态 |
| `POST /api/tickets/transfer` | 管理员 | 转人工，可选择完全按规则执行 |
| `POST /api/tickets/batch-close` | 管理员 | 批量关闭，单批最多 50 单，逐单独立结算 |
| `POST /api/tickets/batch-transfer` | 管理员 | 批量转人工，单批最多 50 单 |
| `GET /api/tickets/stats` | 需登录 | 状态分布、闭环率、平均处理时长；普通用户仅本人 |

字段与示例见[工单与订单 API](tickets-api.md)。

## 错误响应约定

业务错误统一为三键结构，`error_detail` 仅在需要补充上下文时出现：

```json
{
  "error": "非法状态流转：closed -> open",
  "error_code": "TICKET_INVALID_TRANSITION",
  "error_detail": {"from_status": "closed", "to_status": "open"}
}
```

状态码口径固定：401 未登录或令牌无效、403 权限不足、404 资源不存在、409 业务规则拒绝、422 入参越界。未登录与越权优先于入参校验，因此越权请求不会因参数错误而泄露资源是否存在。

### 错误码分族

| 前缀 | 范围 | 示例 |
|---|---|---|
| `AUTH_` | 认证与令牌 | `AUTH_TOKEN_EXPIRED`、`AUTH_WEAK_PASSWORD`、`AUTH_FORBIDDEN` |
| `ORDER_` | 订单业务 | `ORDER_NOT_FOUND`、`ORDER_INVALID_FILTER`、`ORDER_INVALID_TRANSITION` |
| `TICKET_` | 工单业务，含挂在同一路由下的订单接口的身份与入参错误 | `TICKET_UNAUTHORIZED`、`TICKET_INVALID_PAGINATION`、`TICKET_TRANSFER_RULE_NOT_MATCHED` |

三族互不借用，调用方按前缀即可判断问题归属。两处例外是为兼容既有页面：登录失败返回 200 与空令牌，不以 401 表达「密码错误」；`GET /api/me` 未登录时返回 200 与 `user=null`。

## 数据模型与迁移

模块涉及的 8 张表：

| 表 | 模块 | 用途 |
|---|---|---|
| `users` | 认证 | 账号、密码哈希、角色 |

```bash
python -m alembic current
python -m alembic upgrade head
python -m alembic check
```

## 验证方式

```bash
# 依赖
pip install -r backend/requirements.txt -r backend/requirements-dev.txt

# 全量测试
python -m pytest backend/tests -q

# 启动
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

当前状态：三模块专项测试 28 个文件、850 个用例，全量 1247 个用例通过。覆盖重点：

- **契约冻结**：三个模块的响应键集合、错误体结构、错误码族、分页元数据算法均有断言，字段增删会立即暴露。
- **口径互证**：列表总数、筛选计数、统计分布、待确认列表四处口径交叉校验；单条判定与跨订单判定、列表摘要与详情逐字段比对。
- **状态机全矩阵**：工单 6×6、订单 3×3 全部流转组合，测试内保留独立契约快照做双向校验。
- **权限矩阵**：匿名、客户、管理员三类身份 × 全部接口，另含「令牌声明提权无效、改库角色即时生效」的用例。
- **边界与异常**：超长、空白、非字符串路径参数、越界分页、非法排序、重复操作等 20 余组场景，要求不出现 5xx。
- **只读性**：查询类接口调用前后对订单、工单、会话做全量快照比对，确保查询不落库。

已知环境注意点：仓库根目录的 `alembic/` 目录会遮蔽已安装的 alembic 包，运行依赖 alembic 的测试（迁移、隔离进程 HTTP 集成）时需单独排除；本地运行如需指定临时目录，应显式设置 `TMPDIR`。

## 已知限制

- **单机 SQLite**：并发写入依赖数据库级锁，不支持多实例共享；高并发场景需换 PostgreSQL。
- **续期不轮换**：续期令牌在有效期内可重复使用，泄露后仅在登出或过期时失效。
- **无密码找回与邮箱验证**：注册即生效，账号恢复依赖管理员操作。
- **无接口级限流**：登录失败次数、建单频率均未限流，依赖上层网关。
- **订单写操作无 HTTP 入口**：状态流转已实现服务层函数（校验先行、写库在后），但未暴露管理接口，当前由归档接口间接驱动。
- **工单统计为实时聚合**：未做缓存或预计算，数据量大时需改为物化统计。
- **令牌密钥回退**：未配置 `AI_NEW_JWT_SECRET` 时使用固定开发密钥，仅适用于本地调试。
- **分页为偏移分页**：翻页期间新增数据可能改变后续页位置，未提供游标分页。
